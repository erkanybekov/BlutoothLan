# Как работает мини-принтер X6h

## Суть
Принтер использует свой протокол X6h (не ESC/POS). Нашли его через reverse engineering приложения "Tiny Print".

## Протокол X6h
Каждый пакет:
```
AA 55 | CMD | 01 | LENGTH(2 байта LE) | PAYLOAD | CRC8 | 0D 0A
```

**Основные команды:**
- `0xA4` - качество печати
- `0xBD` - скорость протяжки
- `0xAF` - энергия нагрева
- `0xBE` - начать печать
- `0xA2` - отправить строку изображения (48 байт = 384 пикселя)
- `0xA1` - протянуть бумагу (в пикселях)

**CRC8:** полином `0x07`

## Bluetooth характеристики
- **Service:** `AE30` или `AE3A`
- **Write:** `AE01` (writeWithoutResponse)
- **Notify:** `AE02` (для ответов принтера)

## Как печатаем
1. `setQuality(0x35)` - лучшее качество
2. `setFeedSpeed(0x30)` - медленная скорость (лучше качество)
3. `setEnergy(0x5000)` - тёмная печать
4. `startPrint()` - начинаем печать
5. Отправляем изображение построчно через `rawScanline()` - каждая строка 48 байт
6. `feedPaper(200)` - протягиваем бумагу
7. `setQuality(0x35)` - сбрасываем состояние для следующей печати

**Задержки:** 3ms между строками, 50ms между командами

## Обработка изображений
- Ресайз до **384 пикселя** ширина
- Grayscale → Floyd-Steinberg dithering
- Настройки: `contrast: 1.3`, `brightness: 0.15`, `threshold: 140`
- Формат: LSB first (младший бит = первый пиксель)

## Где код
- `PrinterService.swift` - протокол X6h, отправка команд
- `ImageProcessor.swift` - обработка изображений
- `PrintView.swift` - UI для печати
- `DetailedView.swift` - кнопка печати на экране устройства

## Важно
- Протокол проприетарный, не ESC/POS
- Нужна характеристика `writeWithoutResponse`
- После каждой печати сбрасываем состояние, иначе не печатает повторно
- Дебаг: кнопка "Probe" проверяет все характеристики
